**Objetivo.** Entregar o CLI `padroes`, que instala o pacote de distribuição num projeto e o confere
(`instalar`, `perfil`, `doctor`, `verificar`, `atualizar`, `remover`, `desligar`, `religar`, com

`padroes_hook.py`, os adaptadores por harness (`harness/<h>/` no pacote), os hooks Git `pre-commit` e

## Contratos

### `padroes.lock.json`

```json
{
  "versao_formato": 1,
  "catalogo": {"nome": "...", "versao": "1.2.0", "commit": "<sha>"},
  "origem": "<pasta ou URL dada>",
  "pacote_sha256": "<sha256 do manifesto.json do pacote>",
  "regras_sha256": "<sha256 de .padroes/regras.json>",
  "harnesses": ["antigravity", "kiro"],
  "perfil": ["construir-com-ia", "..."],
  "ci": "gitlab | github | nenhum",
  "bloco": "AGENTS.md | null",
  "ids_desconhecidos": "falha | aviso",
  "instalado_em": "AAAA-MM-DD",
  "desligado": null,
  "minima": null,
  "arquivos": {"<caminho>": "<sha256>"},
  "blocos": {"<arquivo compartilhado>": "<sha256 do bloco>"},
  "montagens": {"<ponto>/<skill>": ".padroes/skills/<skill>"},
  "montagens_do_projeto": ["<ponto>/<skill> já ocupado pelo projeto"],
  "links_do_projeto": ["CLAUDE.md, quando é link para o AGENTS.md (F4-D17)"],
  "criados": ["<arquivo compartilhado que o padroes criou>"]
}
```

`perfil` é a lista confirmada ou a string `nao-aplicado`. `desligado` é `{"motivo": "...", "data": "..."}`
quando há flag. `instalado_em` só muda quando outra coisa muda, para a reinstalação não alterar nada
(critério 3 do §16).

### Encaixe da F2 (runtime de hook, adaptadores e hooks Git)

- `portal/cli/harness.py` tem a tabela de harness (sinais, ponto de montagem) e `fragmentos_de_hook`,
  que lê `harness/<h>/` do pacote. Na F4 o pacote não traz essa pasta e a função devolve vazio; a F2
  emite os fragmentos e o `instalar` passa a fazer o merge gerenciado deles nos arquivos do harness
  (`.kiro/hooks/`, `.agents/hooks.json`, `.claude/settings.json`, `.codex/hooks.json`).
- O espelho de `.padroes/` já inclui `hooks/` e `git/` quando existirem no pacote; a linha "Hooks
  ativos" do bloco passa a listar os hooks quando `hooks/padroes_hook.py` existir.
- O `doctor` reporta hoje, como aviso, a degradação "sem runtime de hook no pacote"; na F2 o mesmo
  item vira a conferência dos hooks registrados (§8.2, item 2).

## Rollback

Tudo é aditivo. Reverter os commits da branch tira o CLI e as entradas novas do pacote; o pacote antigo
continua válido. No monorepo, `python3 .padroes/padroes.py remover` (ou `git rm -r .padroes
padroes.lock.json .kiro .agents`) desfaz o dogfooding. Num projeto, `padroes remover` devolve os
arquivos compartilhados ao estado anterior (backup em `.padroes/backup/`).

## Riscos

| Risco | Mitigação |
|---|---|
| Pipeline GitLab só com jobs `.pre` não roda (docs.gitlab.com/ci/yaml) | o `doctor` avisa quando o `.gitlab-ci.yml` não tem outro job; a receita orienta |
| MR altera o verificador em `.padroes/` e com isso o que a avalia | `doctor`/`verificar` conferem o SHA-256 de cada arquivo contra o lockfile; CODEOWNERS sobre `.padroes/` e `padroes.lock.json` fica como recomendação (pendência do dono) |
| Link simbólico no Windows | fora do escopo; o `doctor` reporta montagem ausente |
| `.github/workflows/` com `actions/checkout` fixado em tag | `actions/checkout@v7.0.1` (versão publicada conferida em 2026-11-03); pin por SHA fica como pendência |
| `.padroes/` no monorepo confundir o validador ou o ruff | dogfooding roda `validar.py`, `gerar.py`, `ruff` e a suíte com a pasta presente |
| O bloco do `AGENTS.md` dizer "hooks ativos" sem runtime | F4-D10 |
