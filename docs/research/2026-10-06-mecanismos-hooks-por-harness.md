## Padronização cross-harness

**Padrões abertos**
- **AGENTS.md** (https://agents.md/): Markdown livre, "closest AGENTS.md to the edited file wins"; "stewarded by the Agentic AI Foundation under the Linux Foundation"; sem validador nem limite de tamanho no padrão. Lido nativamente pelos 5 harnesses (Claude Code v2.1.277+, Codex, Kiro, Antigravity; Gemini CLI via `context.fileName`).
- **Agent Skills** (https://agentskills.io/specification): `SKILL.md` com `name` (≤64, kebab-case, = nome da pasta), `description` (≤1024), opcionais `license`, `compatibility` (≤500), `metadata`, `allowed-tools` (experimental); `scripts/`, `references/`, `assets/`; progressive disclosure (metadados ~100 tokens, corpo <5.000 tokens, <500 linhas). Validador oficial: `skills-ref validate ./my-skill` (https://github.com/agentskills/agentskills/tree/main/skills-ref). Adotado pelos 5 harnesses; diretório `.agents/skills/` é comum a Codex, Antigravity e Gemini CLI.
- **Agent Plugins 1.0** (https://agent-plugins.org/ · https://github.com/agentplugins/agent-plugins-spec): `plugin.json` (`$schema`, `name`) + `skills/` + `mcp.json`; só esses dois componentes são padronizados; "Reverse-domain extension namespaces let individual clients add behavior" — **hooks ficam no namespace do vendor** (ex.: `extensions.com.openai.hooks` no Codex). TSC com Amazon, Cursor, Microsoft, OpenAI, Vercel. Adotado por Codex e Kiro Powers; Claude Code e Antigravity usam manifests próprios.

**Ferramentas de sincronização**
| Ferramenta | Harnesses (dos 5) | Regras | MCP | Skills | Hooks | Fonte |
|---|---|---|---|---|---|---|
| **rulesync** (dyoshikawa) | `claudecode`, `codexcli`, `kiro`/`kiro-cli`/`kiro-ide`, `antigravity-ide`/`antigravity-cli`, `geminicli`, + `agentsmd`, `agentsskills` (70+ tools) | sim | sim (`.rulesync/mcp.json`) | sim (`.rulesync/skills/`) | **sim** (feature `hooks`, "~40 tools"; gera p.ex. `.kiro/hooks/rulesync.json`); também `permissions`, `commands`, `subagents`, `checks` | https://github.com/dyoshikawa/rulesync |
| **ruler** (intellectronica) | Claude Code, Codex CLI, Antigravity, Gemini CLI, Kiro (32 agentes) | sim (`.ruler/AGENTS.md`, `ruler.toml`) | sim | sim (`.ruler/skills/`) | **não** (não mencionado) | https://github.com/intellectronica/ruler |
| **skills.sh / `npx skills`** (vercel-labs) | Claude Code, Codex, Antigravity, Gemini CLI, Kiro CLI (77 agentes) | não | não | **só skills** (`add/find/update/list/remove/init`; canônico `.agents/skills/`) | não | https://github.com/vercel-labs/skills |
| "agent-rules" | Não existe projeto único com esse nome; achados: `yelmuratoff/agent_sync` (13 tools incl. Claude Code, Gemini CLI, Codex, Antigravity; só regras), `Djiit/dotagent`, `edwarddev0723/ds-agent-rules`. Nenhum trata hooks. | sim | — | — | não | https://github.com/yelmuratoff/agent_sync |

**Conclusão para o desenho**: o único mecanismo cross-harness que hoje propaga hooks é o rulesync. Formato de hooks de Claude Code e Codex é praticamente idêntico (eventos `PreToolUse`/`PostToolUse`/`UserPromptSubmit`/`Stop`/`SessionStart`, exit 2, `additionalContext`, `permissionDecision`); Gemini CLI usa nomes diferentes (`BeforeTool`/`AfterTool`/`BeforeAgent`) mas mesma semântica de exit 2 + JSON `decision`; Kiro bloqueia apenas por exit ≠ 0 sem JSON de decisão; Antigravity bloqueia apenas por JSON `decision` (sem exit code documentado). Um script de hook portátil deve: ler stdin JSON tolerando snake_case (Claude/Codex/Kiro/Gemini) e camelCase (Antigravity); para bloquear, **emitir JSON de deny E sair com 2** (cobre Claude, Codex, Gemini, Kiro); para Antigravity emitir `{"decision":"deny"}` com exit 0.
