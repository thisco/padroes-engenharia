## O que fazer

O `AGENTS.md` do repositório guarda só o que vale em todo turno: a constituição, os parâmetros
mínimos do projeto e a tabela que diz onde ler o resto. A regra do portal é manter o arquivo
abaixo de 30000 bytes; o procedimento de várias etapas vai para uma skill, e os parâmetros de
uma área do projeto vão para um arquivo de `docs/steering/`, que o agente lê só quando a tarefa
pede [ref:sdd-scaffold-readme]. A constituição fica inline, e não num arquivo lido sob demanda,
porque a premissa precisa valer em todo turno [ref:sdd-scaffold-readme].

O motivo é o custo do arquivo sempre carregado. O Claude Code lê o `CLAUDE.md` no início de toda
sessão e orienta ficar abaixo de 200 linhas por arquivo, porque arquivo mais longo consome mais
contexto e reduz a aderência [ref:claude-code-memory]. Os 30000 bytes são um teto, não uma meta:
um arquivo pode passar das 200 linhas sem chegar a eles, e quanto menor, melhor.

## Como aparece quando falta

O `AGENTS.md` cresce a cada MR: entram o procedimento de release, a lista de comandos de cada
serviço, o histórico de decisões. A Thoughtworks relata o mesmo percurso no uso do Spec Kit,
em que acrescentar contexto de projeto continuamente levou a um conjunto de instruções cada vez
maior e, no fim, a context rot, e o time reagiu extraindo orientações reutilizáveis para skills
[ref:thoughtworks-radar-speckit]. A Anthropic descreve o mecanismo: com mais tokens na janela, a
capacidade do modelo de recuperar com precisão o que está nela diminui [ref:anthropic-context-engineering].

Há também um limite duro por ferramenta. O Codex monta a cadeia de instruções no início de cada
execução e para de acrescentar arquivos quando o tamanho combinado chega a `project_doc_max_bytes`,
que vale 32 KiB por padrão [ref:codex-agents-md]. O README do scaffold diz que o Codex trunca o
documento de projeto em 32768 bytes, sem avisar [ref:sdd-scaffold-readme]. Um `AGENTS.md` inchado
pode perder, em silêncio, o trecho do fim.

## Como aplicar

1. Meça o arquivo: `wc -c AGENTS.md`. Se estiver abaixo de 30000 bytes e sem blocos de procedimento
   colados, pule para o passo 5.
2. Não mexa na constituição inline. Num projeto do scaffold ela fica entre os marcadores
   `<!-- constituicao:inicio` e `<!-- constituicao:fim -->`, e o `verificar_constituicao.py`
   reprova se o bloco divergir da cópia canônica [ref:sdd-scaffold-readme].
3. Mova o que não vale em todo turno. Procedimento de várias etapas vira skill, e o que só importa
   a uma parte do código vira arquivo de `docs/steering/` ou regra com escopo de caminho
   [ref:claude-code-memory]. Importar o arquivo com `@` não resolve: os arquivos importados também
   carregam no início, e o custo de contexto continua [ref:claude-code-memory]. Deixe no
   `AGENTS.md` só uma linha que aponta o arquivo.
4. Meça de novo e confirme o tamanho.
5. Ligue o job `governanca` da receita [Ligar o CI do GitLab com as travas](../receitas/ligar-ci-gitlab-travas.html),
   que repete o limite de 30000 bytes do CI do scaffold [ref:sdd-scaffold-qualidade]. Para o
   passo a passo e para baixar os scripts com o hash conferido, siga a receita.

## Exemplo

### Antes e depois

O `AGENTS.md` de um projeto gerado pelo scaffold 1.7.0 tinha 5387 bytes. Depois de colarem nele
200 passos de procedimento, cada um com cerca de 190 bytes, chegou a 44419 bytes. Corrigido, o
procedimento mora em `docs/steering/procedimentos.md`, e o `AGENTS.md` volta a 5482 bytes.

Antes, com o procedimento colado no arquivo carregado em todo turno:

```markdown
<!-- constituicao:fim -->

## Procedimentos detalhados (colados da wiki)

1. Procedimento detalhado do passo 1: leia a spec, confira o plano, rode a suíte completa, cole a evidência no plano, atualize o CHANGELOG e peça a revisão a quem não escreveu o código.
...
200. Procedimento detalhado do passo 200: leia a spec, confira o plano, rode a suíte completa, cole a evidência no plano, atualize o CHANGELOG e peça a revisão a quem não escreveu o código.
```

Para reproduzir o estado "antes" num projeto de teste, acrescente os 200 passos ao fim do
`AGENTS.md` (as linhas acima só encurtam o que o comando gera):

```bash
{ printf '\n## Procedimentos detalhados (colados da wiki)\n\n'; for i in $(seq 1 200); do
  echo "$i. Procedimento detalhado do passo $i: leia a spec, confira o plano, rode a suíte completa, cole a evidência no plano, atualize o CHANGELOG e peça a revisão a quem não escreveu o código."
done; } >> AGENTS.md
wc -c AGENTS.md
```

Depois, com uma linha de roteamento:

```markdown
Procedimentos detalhados: `docs/steering/procedimentos.md`, lido só nas tarefas que o pedem.
```

O job `governanca` do arquivo `exemplos/P1-03/gitlab-ci.yml` reprovou o primeiro estado e aprovou
o segundo. Execução com `gitlab-ci-local` 4.76.0, no executor Docker:

```text
governanca > AGENTS.md com 44419 bytes (limite 30000)
governanca > AGENTS.md grande demais; mova o detalhe para docs/steering/
governanca finished in 667 ms  FAIL 1
```

```text
governanca > AGENTS.md com 5482 bytes (limite 30000)
governanca > Constituição padrao-v1.0: bloco inline confere com o arquivo canônico.
governanca finished in 775 ms
 PASS  governanca
```

### Para o agente

Regra curta para o `AGENTS.md`:

```markdown
O AGENTS.md fica abaixo de 30000 bytes. Procedimento de várias etapas vai para skills e detalhe
de uma área do projeto vai para docs/steering/; aqui entra só uma linha apontando o arquivo.
```

Prompt para reduzir um `AGENTS.md` grande demais:

```prompt
Aplique a prática P1-03 do portal de padrões de engenharia ao AGENTS.md deste repositório.
Limite: {limite em bytes, 30000 se eu não disser outro}.

1. Rode wc -c AGENTS.md e me diga o tamanho. Se for menor que o limite, pare e diga que não há
   nada a fazer.
2. Se for igual ou maior, mova para docs/steering/{arquivo de destino}.md os trechos que só
   importam a uma parte do projeto (procedimentos passo a passo, listas de comandos, histórico
   de decisões). Não altere o bloco entre "<!-- constituicao:inicio" e "<!-- constituicao:fim -->"
   nem a tabela de roteamento. No lugar de cada trecho movido, deixe no AGENTS.md uma linha que
   aponte o arquivo e diga quando ele é lido. Crie a pasta docs/steering/ se ela não existir.
3. Rode wc -c AGENTS.md de novo. Se continuar igual ou maior que o limite, repita o passo 2 com
   outros trechos.
4. Se existir scripts/verificar_constituicao.py, rode python3 scripts/verificar_constituicao.py
   --raiz . e me mostre a saída. Mostre também os dois tamanhos medidos.
5. Não altere nenhum outro arquivo e não faça commit.
```

### Por ferramenta

No Codex, o limite que importa é o `project_doc_max_bytes`, de 32 KiB por padrão
[ref:codex-agents-md]. No Claude Code, o `AGENTS.md` entra pelo `CLAUDE.md` com `@AGENTS.md`
[ref:claude-code-memory]; vale a recomendação de ficar abaixo de 200 linhas [ref:claude-code-memory].

## Como verificar

Esta prática não declara mecanismo: o portal só registra como mecanismo um script hospedado em
`/.well-known/mecanismos/` ou um arquivo de `scripts/` do próprio repositório, e a conferência
do tamanho mora num job de CI. O verificador candidato é o job `governanca` da receita
[Ligar o CI do GitLab com as travas](../receitas/ligar-ci-gitlab-travas.html), que repete o limite
de 30000 bytes do CI do scaffold, descrito ali como limite de alerta antes do truncamento real em
32768 [ref:sdd-scaffold-qualidade]. O job faz duas conferências: a contagem de bytes do `AGENTS.md`,
que reprova o pipeline da MR a partir de 30000 bytes, e o `verificar_constituicao.py`, hospedado
em `/.well-known/mecanismos/sdd-scaffold/`, que reprova a constituição inline adulterada. O
script confere a constituição, não o tamanho; o tamanho é conferido pela contagem do próprio
job. O arquivo do job está em `exemplos/P1-03/gitlab-ci.yml`:

<!-- incluir: exemplos/P1-03/gitlab-ci.yml -->

O job reprova o pipeline, mas só impede o merge se a opção **Pipelines must succeed** estiver marcada no projeto, como a
receita explica. Ela conta bytes, não tokens, e não olha o conteúdo de `docs/steering/`: um
arquivo de steering gigante que o agente lê em toda tarefa passa sem aviso. O Spec Kit tem
mecanismo parecido para outro objeto: os templates de plano exigem passar por gates da
constituição ou documentar a exceção [ref:speckit-spec-driven].
